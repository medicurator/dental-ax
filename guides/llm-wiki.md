# Claude Code와 옵시디언으로 개인 위키 만들기

Claude Code와 나눈 대화는 세션을 닫으면 사라집니다. 이 안내서는 가치 있는 대화를 "위키에 추가해줘" 한마디로 옵시디언 문서로 남기고, 다음에 "위키에서 찾아봐"로 다시 꺼내 쓰는 구조를 만드는 방법입니다.

끝까지 따라 하면 이렇게 됩니다.

- 어느 프로젝트의 Claude Code 세션에서든 "위키에 추가해줘"라고 하면 그 내용이 위키 문서로 정리됩니다.
- 옵시디언으로 위키 폴더를 열면 문서들이 링크와 그래프로 연결돼 보입니다.
- "위키에서 찾아봐"라고 하면 Claude가 위키 문서를 근거로 답합니다.

## 한눈에 보는 구조

```
[어느 프로젝트의 Claude Code 세션]
        │  "위키에 추가해줘"
        ▼
   위키 스킬 (모든 세션에서 쓸 수 있게 설치)
        │
        ▼
위키 폴더 (옵시디언 볼트)
├─ CLAUDE.md   # 위키 규칙: 문서 형식, 분류, 가릴 정보
├─ index.md    # 전체 목차
├─ log.md      # 변경 기록
├─ raw/        # 대화에서 뽑은 원문 메모
└─ wiki/       # 정리된 문서 (주제별 폴더)
```

| 구성 | 어디에 두나 | 이유 |
|---|---|---|
| 위키 스킬 3개 | 전역 (사용자 범위 플러그인) | 어느 프로젝트 세션에서든 불러야 하므로 |
| 위키 폴더 위치 | 전역 (`~/.claude/CLAUDE.md`에 한 줄) | 어느 세션이든 같은 위키에 쓰도록 |
| 위키 규칙 | 위키 폴더 안 (`CLAUDE.md`) | 위키를 다루는 스킬만 알면 되므로 |

Claude Code에서 `~/.claude/` 아래는 모든 세션에 적용되는 전역이고, 프로젝트 폴더 안의 `CLAUDE.md`는 그 폴더에만 적용되는 지역입니다. 여러 프로젝트에서 써야 하는 것은 전역에, 한 폴더만 알면 되는 것은 지역에 둡니다.

## 준비물

- Claude Code 최신 버전과 터미널에서 쓸 수 있는 `claude` 명령
- 옵시디언 (무료, obsidian.md)
- Git과 GitHub 계정 (백업을 할 경우)

아래에서는 위키 폴더를 `C:\Wiki`, 스킬 폴더를 `C:\claude-mods\wiki`로 적습니다. Mac에서는 `~/Wiki`, `~/claude-mods/wiki`처럼 바꿔 읽으면 됩니다.

## 만들기 전에 정할 것

구조는 같아도 아래 네 가지는 사람마다 다릅니다. 먼저 정해 두면 뒤가 쉽습니다.

| 정할 것 | 이 안내서의 선택 | 이유 |
|---|---|---|
| 언제 수집하나 | 요청할 때만 ("위키에 추가해줘") | 모든 대화를 자동으로 모으면 쓸모없는 내용이 쌓이고 비용도 듭니다 |
| 어떻게 분류하나 | 주제별 폴더 | 프로젝트별로 나누면 여러 프로젝트에 걸친 지식이 흩어집니다 |
| 민감한 정보 | 가린 뒤 저장 | 환자 정보, 비밀번호, API 키가 위키와 백업에 남지 않게 합니다 |
| 언제 읽나 | 요청할 때만 ("위키에서 찾아봐") | 평소 세션의 비용이 늘지 않습니다 |

## 1단계: 위키 폴더 만들기

`C:\Wiki` 폴더를 만들고 그 폴더에서 Claude Code를 엽니다. 그리고 이렇게 요청합니다.

```
이 폴더를 위키 볼트로 만들어줘. raw 폴더, wiki 폴더, index.md(주제별 목차), log.md(변경 기록)를 만들고,
wiki 아래에는 주제 폴더를 만들어줘: 진료, 경영, 클로드코드, 옵시디언
```

주제 폴더 이름은 본인이 자주 다루는 주제로 바꿉니다. 처음에는 4~5개면 충분하고, 문서가 쌓이면 나중에 늘립니다.

## 2단계: 위키 규칙 넣기

위키 폴더에 `CLAUDE.md` 파일을 만들고 아래 내용을 넣습니다. 이 파일이 위키의 규칙이고, 스킬은 작업 전에 이 파일을 읽고 따릅니다. 주제 폴더 목록과 가릴 정보는 본인에게 맞게 고칩니다.

<details>
<summary>위키 규칙 파일 (CLAUDE.md) 펼치기</summary>

````markdown
# 위키 규칙

이 폴더는 옵시디언 볼트이자 Claude Code 세션에서 쌓는 개인 위키다. `wiki-add`, `wiki-query`, `wiki-lint` 스킬은 작업 전에 이 문서를 읽고 그대로 따른다.

## 폴더

| 경로 | 내용 | 규칙 |
|---|---|---|
| `raw/` | 대화에서 뽑은 원문 메모 | 한 번 쓰면 고치지 않는다. 마스킹 누락을 고칠 때만 예외 |
| `wiki/<주제>/` | 정리된 문서 | 주제별 폴더. 프로젝트 이름으로 폴더를 만들지 않는다 |
| `index.md` | 전체 목차 | 문서를 추가·이동·삭제하면 함께 고친다 |
| `log.md` | 변경 기록 | 최신 항목이 위. 지우지 않는다 |

주제 폴더: `진료`, `경영`, `클로드코드`, `옵시디언`. (본인의 주제로 바꾼다)
맞는 폴더가 없으면 가장 가까운 폴더에 넣는다. 새 폴더는 한 폴더의 문서가 10개 이상이고 그 안에 같은 주제 문서가 여럿 모였을 때 `wiki-lint`가 제안하고 사용자가 승인하면 만든다.

## 이름

- 위키 문서: 한글 제목 그대로. 예: `API 키 등록 - 환경변수와 .env.md`. 파일 이름에 쓸 수 없는 문자(`: / \ ? * " < > |`)는 ` - `로 바꾸거나 뺀다.
- 원문 메모: `raw/YYYY-MM-DD-주제.md`. 주제는 영문 소문자와 하이픈. 같은 날 같은 주제면 `-2`를 붙인다.
- 문서 제목(`# 제목`)과 파일 이름은 같게 한다(파일 이름에서 바꾼 문자 제외).

## 위키 문서 템플릿

```markdown
---
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [주제폴더, 키워드]
sources: [프로젝트이름]
---
# 제목

> 한 줄 요약

## 핵심
## 상세
## 관련 문서
## 출처
```

- `created`는 처음 만든 날, `updated`는 마지막으로 고친 날.
- `tags` 첫 항목은 주제 폴더 이름. 나머지는 소문자 키워드 1~4개.
- `sources`는 내용이 나온 프로젝트 이름(세션의 작업 폴더 이름). 병합할 때 누적한다.
- **핵심**: 3~6개 불릿 또는 표 하나. 이것만 읽어도 답이 되게 쓴다.
- **상세**: 근거, 예시, 명령어, 주의점. 소제목(`###`)으로 나눌 수 있다.
- **관련 문서**: `- [[문서 제목]] — 왜 관련 있는지`. 없으면 `- 없음`.
- **출처**: `- raw/파일이름.md (YYYY-MM-DD, 프로젝트)`. 문서의 모든 주장은 출처의 원문 메모 중 하나로 거슬러 올라갈 수 있어야 한다.
- 결과물(보고서·HTML·docx 등) 문서는 같은 템플릿을 쓰고, 상세에 `원본: <절대 경로>`를 적는다. 파일은 볼트로 복사하지 않는다.

## 원문 메모 형식

```markdown
---
date: YYYY-MM-DD
project: 프로젝트이름
session: 세션 id 또는 "알 수 없음"
topic: 한 줄 주제
---
(대화에서 해당 주제에 관한 질문과 답을 요약하지 않고 옮긴다. 주제와 무관한 부분은 뺀다.)
```

## 문체

- 한국어 평서문(~다). 명령어, 코드, 파일 이름, 고유명사는 원문 그대로.
- 대화의 맥락("방금 확인했는데", "이 프로젝트에서는")은 누가 읽어도 통하는 문장으로 바꾼다. 특정 프로젝트에만 해당하는 내용은 "○○ 프로젝트에서는"처럼 프로젝트를 밝힌다.
- 확실하지 않은 내용은 쓰지 않거나 "확인 필요"라고 표시한다.

## 링크

- 볼트 안 문서는 `[[문서 제목]]`으로 건다. 존재하지 않는 문서로 링크를 걸지 않는다.
- 새 문서를 만들면 관련 문서 쪽에도 되돌아오는 링크를 추가한다.

## 민감정보 마스킹

`raw/`에 쓰기 전에 가린다. 가리지 않은 원문은 볼트 어디에도 남기지 않는다.

| 대상 | 처리 |
|---|---|
| API 키, 토큰, 비밀번호, 인증 헤더 | 접두어만 남기고 `***`. 예: `sk-***`, `ghp_***`. 접두어가 없으면 `***` |
| 환자 이름, 주민등록번호, 차트 번호, 연락처 | 이름은 `홍○○`, 번호는 `***` |
| 거래처·직원 등 실명 개인, 계좌·카드 번호 | 이름은 `김○○`, 번호는 `***` |
| 거래처 회사 이름, 금액 | 지식 이해에 필요 없으면 `A사`, `***원` |
| 이메일, 전화번호 | `***` |

환경변수 **이름**(`MY_API_KEY`)은 비밀이 아니므로 그대로 둔다. 가릴지 애매하면 가린다.

## 병합

같은 주제의 문서가 이미 있으면 새로 만들지 않고 그 문서를 고친다. 기존 내용과 새 내용이 어긋나면 덮어쓰지 말고, 어느 쪽이 맞는지 사용자에게 묻는다. 맞는 쪽을 남기고 `log.md`에 무엇이 바뀌었는지 적는다.

## index.md 형식

주제 폴더별 절 아래에 `- [[문서 제목]] — 한 줄 요약`을 가나다순으로 둔다.

## log.md 형식

```markdown
## YYYY-MM-DD
- 추가: [[문서 제목]] (출처: 프로젝트)
- 병합: [[문서 제목]] — 무엇을 더했는지
- 점검: 무엇을 고쳤는지
```

## git

문서를 바꾼 작업은 끝에 커밋한다. 메시지는 `add: 문서 제목`, `merge: 문서 제목`, `lint: 요약`. 원격 저장소가 연결돼 있으면 푸시한다.
````

## 3단계: 스킬 만들기

스킬은 Claude가 정해진 순서대로 일하게 하는 지침 파일입니다. 세 개를 만듭니다.

| 스킬 | 부르는 말 | 하는 일 |
|---|---|---|
| `wiki-add` | "위키에 추가해줘" | 수집 → 정리 → 연결 → 점검 → 기록 → 커밋 |
| `wiki-query` | "위키에서 찾아봐" | 목차와 문서를 읽고 근거와 함께 답변 |
| `wiki-lint` | "위키 점검해줘" | 위키 전체를 검사해 보고하고, 승인받은 것만 수정 |

`C:\claude-mods\wiki` 폴더에 아래 구조로 파일을 만듭니다.

```
wiki/
├─ .claude-plugin/
│  ├─ plugin.json
│  └─ marketplace.json
└─ skills/
   ├─ wiki-add/SKILL.md
   ├─ wiki-query/SKILL.md
   └─ wiki-lint/SKILL.md
```

`.claude-plugin/plugin.json`:

```json
{
  "name": "wiki",
  "version": "0.1.0",
  "description": "어느 세션에서든 대화 내용을 옵시디언 위키에 추가하고, 찾아보고, 점검한다"
}
```

`.claude-plugin/marketplace.json`:

```json
{
  "name": "wiki-local",
  "owner": { "name": "본인 이름" },
  "plugins": [{ "name": "wiki", "source": "./" }]
}
```

````markdown
---

# wiki-add

현재 세션의 대화에서 사용자가 가리킨 주제를 위키 문서로 만든다. 아래 순서를 건너뛰거나 바꾸지 않는다.

## 0. 준비

1. 볼트 경로를 정한다. 전역 지침(`~/.claude/CLAUDE.md`)의 "위키 볼트" 항목을 쓴다. 없으면 `C:\Wiki`. 폴더가 없으면 멈추고 사용자에게 알린다.
2. `<볼트>/CLAUDE.md`를 읽는다. 템플릿, 이름, 문체, 마스킹, 병합 규칙은 모두 그 문서를 따른다. 이 스킬과 어긋나면 볼트의 CLAUDE.md가 우선한다.
3. 무엇을 추가할지 정한다. 사용자가 주제를 말했으면 그것, "방금 내용"이라고 했으면 직전의 질문과 답이다. 대화에 주제가 여럿이고 어느 것인지 알 수 없을 때만 묻는다.
4. 오늘 날짜와 프로젝트 이름(현재 작업 폴더의 이름)을 확인한다.

## 1. 수집 (ingest)

1. 대화에서 그 주제의 질문과 답을 뽑는다. 요약하지 않고 옮기되 주제와 무관한 부분은 뺀다. 이 세션의 대화에 없는 내용을 지어내 보태지 않는다.
2. **쓰기 전에 마스킹한다.** 볼트 CLAUDE.md의 마스킹 표대로 가린다. 가린 항목의 종류와 개수를 기억해 두었다가 마지막 보고에 적는다(값 자체는 적지 않는다).
3. `raw/YYYY-MM-DD-주제.md`에 원문 메모 형식으로 저장한다.
4. 결과물 파일(보고서, HTML, docx 등)을 추가하는 경우에는 파일을 복사하지 않는다. 원문 메모에 파일의 절대 경로, 무엇인지, 왜 만들었는지, 핵심 내용을 적는다.

## 2. 정리 (compile)

1. 기존 문서를 찾는다. `index.md`를 읽고, 주제의 핵심 낱말 2~3개로 `wiki/` 아래를 검색한다(제목, 태그, 본문).
2. 같은 주제의 문서가 있으면 **새로 만들지 않고 그 문서에 병합한다.** 빠진 내용을 맞는 절에 더하고, `updated`를 오늘로, `sources`에 프로젝트를, 출처에 새 원문 메모를 추가한다. 기존 내용과 어긋나는 부분이 있으면 덮어쓰지 말고 사용자에게 어느 쪽이 맞는지 묻는다.
3. 없으면 템플릿대로 새 문서를 쓴다. 주제 폴더와 파일 이름은 볼트 규칙을 따른다.
4. 대화체를 위키 문체로 바꾼다. 특정 프로젝트에만 해당하는 내용은 프로젝트 이름을 밝힌 소제목 아래에 둔다.
5. 한 번에 주제가 둘 이상 섞여 있으면 문서를 나눈다.

## 3. 연결 (link)

1. 관련 문서를 찾아 `## 관련 문서`에 `[[문서 제목]] — 이유`로 건다. 존재하는 문서만 건다.
2. 링크한 상대 문서의 `## 관련 문서`에도 되돌아오는 링크를 추가하고 그 문서의 `updated`를 고친다.
3. `index.md`의 해당 주제 절에 `- [[문서 제목]] — 한 줄 요약`을 가나다순 자리에 넣는다. 병합이면 요약이 달라졌을 때만 고친다.

## 4. 점검 (lint)

이번에 만들거나 고친 파일만 검사한다. 문제를 찾으면 바로 고치고, 고칠 수 없는 것은 보고에 적는다.

- 프론트매터의 필드 5개가 다 있고 날짜 형식이 맞는가
- 템플릿의 절(핵심, 상세, 관련 문서, 출처)이 다 있는가
- `[[링크]]`가 모두 실제 파일을 가리키는가
- 출처의 원문 메모 파일이 실제로 있는가
- 문서의 주장 중 원문 메모에 없는 것이 있는가 (있으면 지운다)
- 마스킹 재확인: 이번에 쓴 raw와 wiki 파일에서 `sk-`, `ghp_`, `Bearer `, `api_key`, `password`, 긴 영숫자 문자열(32자 이상), 전화번호·이메일·주민번호 모양을 검색해 가려지지 않은 값이 없는지 본다
- 결과물 문서라면 적어 둔 원본 경로에 파일이 있는가

## 5. 기록 (log)

`log.md`의 오늘 날짜 절(없으면 맨 위에 새로 만든다)에 `- 추가: [[제목]] (출처: 프로젝트)` 또는 `- 병합: [[제목]] — 무엇을 더했는지`를 적는다.

## 6. 커밋

볼트가 git 저장소면 볼트 폴더에서 바뀐 파일을 커밋한다. 메시지는 `add: 제목` 또는 `merge: 제목`. 원격(`origin`)이 있으면 푸시하고, 푸시가 실패하면 커밋은 그대로 두고 실패를 보고한다. git 저장소가 아니면 이 단계를 건너뛰고 보고에 적는다.

현재 프로젝트의 저장소가 아니라 **볼트의 저장소**에 커밋한다. `git -C <볼트>`를 쓴다.

## 7. 보고

짧게 보고한다.

- 원문 메모 경로

- 마스킹한 항목의 종류와 개수 (없으면 "없음")
- 점검에서 고친 것과 남은 문제
- 커밋·푸시 결과
````

````markdown
위키 문서를 근거로 질문에 답한다. 볼트의 파일은 고치지 않는다.

## 순서

1. 볼트 경로를 정한다. 전역 지침(`~/.claude/CLAUDE.md`)의 "위키 볼트" 항목, 없으면 `C:\Wiki`.
````

````markdown
# wiki-lint

볼트 전체를 검사한다. **먼저 보고하고, 사용자가 승인한 것만 고친다.** 예외는 마스킹 누락이다(아래 참조).

## 0. 준비

1. 볼트 경로를 정한다. 전역 지침(`~/.claude/CLAUDE.md`)의 "위키 볼트" 항목, 없으면 `C:\Wiki`.
2. `<볼트>/CLAUDE.md`를 읽는다. 검사 기준은 그 문서의 규칙이다.
3. `wiki/`와 `raw/`의 파일 목록, `index.md`, `log.md`를 읽는다.

## 1. 검사 항목

| # | 항목 | 찾는 것 |
|---|---|---|
| 1 | 마스킹 누락 | raw와 wiki에서 가려지지 않은 키·토큰·비밀번호, 환자·개인 식별 정보, 이메일·전화번호 |
| 2 | 끊어진 링크 | 없는 문서를 가리키는 `[[링크]]`, 없는 raw 파일을 가리키는 출처 |
| 3 | 끊어진 경로 | 결과물 문서의 `원본:` 경로에 파일이 없음 |
| 4 | 형식 | 프론트매터 필드 누락, 템플릿 절 누락, 제목과 파일 이름 불일치, 이름 규칙 위반 |
| 5 | 목차 | `index.md`에 없는 문서, 문서가 없는 목차 항목, 한 줄 요약이 본문과 다름 |
| 6 | 중복 | 같은 주제를 다루는 문서 둘 이상 (제목·태그·핵심 절을 비교) |
| 7 | 모순 | 문서끼리 서로 어긋나는 주장 |
| 8 | 출처 없는 주장 | 출처의 원문 메모로 거슬러 올라갈 수 없는 내용 |
| 9 | 고립 | 들어오는 링크도 나가는 링크도 없는 문서 (연결할 문서가 있는지 제안) |
| 10 | 분류 | 폴더가 맞지 않는 문서, 한 폴더의 문서가 볼트 규칙의 기준(기본 10개) 이상이라 새 폴더가 필요한 경우 |
| 11 | 낡은 내용 | 버전·날짜·경로처럼 변하기 쉬운 사실이 오래된 문서 |

문서가 많으면 1~5번은 검색과 스크립트로 전체를 보고, 6~11번은 `index.md`와 각 문서의 핵심 절을 읽어 판단한다.

## 2. 마스킹 누락은 즉시 고친다

가려지지 않은 비밀값이나 개인 식별 정보를 찾으면 승인을 기다리지 않고 바로 가린다. 그리고 보고 맨 위에 적는다. 어느 파일에서 어떤 종류를 가렸는지만 적고 값은 적지 않는다.

볼트가 git 저장소이고 그 값이 이미 커밋됐다면 이력에 남아 있다는 점, 원격에 푸시됐다면 해당 키를 폐기하고 새로 발급받아야 한다는 점을 알린다. 이력을 다시 쓰는 일은 사용자가 지시할 때만 한다.

## 3. 보고

항목별로 묶어 표로 보고한다. 각 줄에 파일, 문제, 고치는 방법을 적는다. 문제가 없는 항목은 "이상 없음" 한 줄로 끝낸다. 맨 끝에 문서 수, raw 메모 수, 주제 폴더별 문서 수를 적는다.

## 4. 수정

1. 사용자가 고르거나 "전부 고쳐줘"라고 한 것만 고친다.
2. 중복 병합: 내용을 한 문서로 합치고, 없어지는 문서를 가리키던 링크를 모두 남는 문서로 바꾼 뒤 지운다. 두 문서의 출처와 `sources`를 합친다.
3. `raw/`의 원문 메모는 마스킹 외에는 고치거나 지우지 않는다.
4. 고친 문서의 `updated`를 오늘로 바꾸고 `index.md`를 맞춘다.
5. `log.md`의 오늘 절에 `- 점검: 무엇을 고쳤는지`를 적는다.
6. 볼트가 git 저장소면 `git -C <볼트>`로 커밋한다. 메시지는 `lint: 요약`. 원격이 있으면 푸시한다.
````


저장소는 반드시 **비공개**로 만듭니다. 위키에는 본인의 대화가 들어 있습니다. 한 번 연결해 두면 스킬이 추가하거나 점검할 때마다 커밋하고 올립니다.

## 써 보기

아무 프로젝트에서 Claude Code와 대화하다가 남길 만한 설명이 나오면 이렇게 말합니다.

```
방금 내용 위키에 추가해줘
```

Claude가 원문 메모를 저장하고, 문서로 정리하고, 관련 문서와 연결한 뒤 결과를 보고합니다. 같은 주제의 문서가 이미 있으면 새로 만들지 않고 그 문서에 합칩니다.

| 하고 싶은 일 | 이렇게 말합니다 |
|---|---|
| 대화 내용을 남기기 | "위키에 추가해줘", "○○를 위키에 추가해줘" |
| 위키에서 찾아 답하기 | "위키에서 ○○ 찾아봐" |
| 위키 전체 점검 | "위키 점검해줘" |

정확한 문장이 아니어도 뜻이 맞으면 실행됩니다. 조회는 "위키"라는 말이 들어가야 실행됩니다.

## 운영하면서 알게 된 것

- **다시 찾아볼 것만 추가합니다.** 위키에 쓰는 작업은 읽는 것보다 훨씬 많은 사용량이 듭니다. 한 번 하고 끝나는 일의 경과는 남기지 않습니다.
- **확실하지 않은 내용에는 "확인 필요"를 붙입니다.** Claude가 기억으로 답한 메뉴 이름이 실제 화면과 다른 경우가 있었습니다. 표시해 둔 덕에 나중에 고칠 곳을 알 수 있었습니다.
- **점검을 가끔 돌립니다.** 위키는 쌓일수록 겹치는 내용과 낡은 내용이 생깁니다. "위키 점검해줘"가 확인되지 않은 설명과, 내용이 제목보다 넓어진 문서를 실제로 잡아냈습니다.
- **원문 메모는 고치지 않습니다.** 문서가 여러 번 합쳐져 바뀌어도 원문 메모가 남아 있어 내용의 출처를 거슬러 올라갈 수 있습니다.
- **위키는 비공개로 둡니다.** 다른 사람에게 줄 자료는 위키를 공개하지 말고, 필요한 것만 골라 읽는 사람에 맞게 다시 써서 따로 공유합니다.

## 주의할 점

- **환자 정보와 비밀값**: 규칙 파일의 "민감정보 마스킹" 표가 가릴 대상을 정합니다. 진료 관련 대화를 남길 일이 있다면 이 표를 먼저 본인 환경에 맞게 고치고, 추가한 뒤 결과 보고의 "마스킹한 항목"을 확인합니다. 가려졌는지는 사람이 한 번 더 봐야 합니다.
- **Claude 채팅에서는 동작하지 않습니다.** 스킬은 이 컴퓨터의 Claude Code에 설치되므로, 웹이나 앱의 채팅에서는 "위키에 추가해줘"가 실행되지 않습니다. 채팅에서 나온 내용은 Claude Code 세션에 붙여넣고 추가합니다.
- **다른 폴더에 쓸 때 권한을 물을 수 있습니다.** 다른 프로젝트 세션에서 위키 폴더에 처음 쓸 때 허용 여부를 묻습니다.

## 확인된 범위

이 구조는 Windows 11, Claude Code 2.1.325, Obsidian 1.15.1에서 만들어 사용했습니다. 위키 폴더에서 연 세션에서 세 스킬이 모두 동작하는 것을 확인했습니다. 아래는 아직 확인하지 않았습니다.
